## Circuit Scope Check

The planned presentation description is correct with the following wording:

- The standard evaluation target is not a full QPE circuit.
- The standard evaluation target is the controlled product-formula one-step
  kernel used by QPE.
- The standard scope is `efficient_controlled_pf_one_step`.
- Full QPE phase register, multiple controlled powers, inverse QFT,
  measurement, feed-forward, and eigenstate preparation are not included.
- QPE-scale totals are linear extrapolations from one-step results using
  `qpe_action_count`.
- `controlled_pf_time_evolution_block` is a correctness / qret-pipeline
  baseline, not the standard QPE-total scaling target.

README and `architecture_sweep.py` agree that efficient controlled rows use
`linear_extrapolation_from_efficient_controlled_pf_one_step`, while generic
controlled rows use `none_single_controlled_block` and leave QPE-total fields
unavailable.

## Logical-Cell Placement Check

The implementation explicitly appends the control qubit as the last circuit
logical index. It does not manually place that control qubit at a specific
coordinate on the 10 x 10 logical-cell grid.

The topology sweep and magic-supply sweep artifacts have
`mapping_result_json` disabled. Therefore, these artifacts do not expose the
final qret Mapping-stage coordinates of system qubits or the control qubit.
The accurate presentation wording is:

- The control qubit is added as the last logical index in the circuit.
- Placement on the 10 x 10 logical-cell grid is determined by qret Mapping.
- The coordinates explicitly varied in these sweeps are magic-state factory
  coordinates.

Do not write that the control qubit was placed at the center cell.

## Metric Meaning

| metric | meaning | observed or extrapolated | scaling note |
|---|---|---|---|
| `runtime_with_topology` / presentation `runtime` | one-step qret profile runtime with topology | observed one-step profile result | can be multiplied by `qpe_action_count` for the current linear total |
| `runtime_without_topology` | one-step topology-free runtime field from compile info | observed one-step profile field | can be multiplied when present, but compare carefully against topology-aware runtime |
| `total_runtime_with_topology` / presentation `total_runtime` | QPE-scale runtime estimate | linear extrapolation | one-step runtime x `qpe_action_count` |
| `qubit_volume` | one-step topology-aware qubit-volume metric | observed one-step profile result | can be multiplied by `qpe_action_count` for the current linear total |
| `total_qubit_volume` | QPE-scale qubit-volume estimate | linear extrapolation | one-step qubit volume x `qpe_action_count` |
| `chip_cells` | exposed chip logical-cell count | observed/profiled one-step resource field | do not multiply when describing chip size |
| `physical_qubits` | QEC physical-qubit estimate for one profiled architecture condition | observed/profiled field | do not multiply by QPE action count as a total |
| `code_distance` | QEC code distance chosen/reported for the one-step profile | observed/profiled field | do not multiply |
| `step_magic_state_count` | one-step logical magic-state consumption count | observed one-step circuit/profile field | total field is linearly scaled |
| `step_magic_state_depth` | one-step magic-state consumption depth | observed one-step circuit/profile field | total field is linearly scaled in current outputs |
| `qpe_action_count` | action count inferred from PF coefficient/order and target error | estimated input to extrapolation | not a qret-observed full-QPE iteration count |

## Discussion Validity

Supported as observed:

- Factory placement has negligible runtime effect in this sweep; max topology
  runtime spread is 0.0364%.
- Factory placement has a consistent qubit-volume effect; center-block is
  minimum in 40/40 fixed molecule/PF/magic groups.
- Magic-state count and magic-state depth are invariant across the magic
  supply sweep for fixed molecule/PF.
- Period 1 and period 1 with large stock match exactly in the magic-supply
  artifact.

Supported as inference, not direct observation:

- The qubit-volume gap is likely due to active area, delivery geometry,
  routing, or mapping occupancy rather than runtime, because runtime and
  exposed chip-cell fields barely move.
- For larger H-chain cases, magic generation period is likely not the dominant
  runtime bottleneck under the tested center-topology setup.
- Logical dependencies, lattice-surgery operation scheduling, routing, or
  mapping may dominate runtime in larger cases.

Unresolved / limited:

- The current topology and magic-supply artifacts have `mapping_result_json`
  disabled, so final logical-cell coordinates for system/control qubits are
  not available from these sweep outputs.
- The critical path was not decomposed; bottleneck explanations should remain
  inferred.
- The internal cause of qubit-volume movement beyond exposed `chip_cells`,
  `physical_qubits`, and `code_distance` requires additional diagnostics.

The resolved m0 issue is not treated as an unresolved problem in this report.
